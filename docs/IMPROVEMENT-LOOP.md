# 概念地图 · Agent Loop（持续体验提升）

## 为什么上一版会乱

三件事叠在一起：

1. **确认权分散**：验收/实现各自向用户二次确认，而用户意图只在编排对话里说过一次。
2. **没有单一编排**：两边互相叫醒、主代理又重复踢门，造成多入口重启。
3. **结束条件模糊**：工程缺陷收工 ≠ 体验满意；目标切换时没有显式「换轨」。

本文件是唯一权威流程。与此冲突的口头约定一律作废。

## 三角色（严格分工）

| 角色 | Agent | 唯一职责 |
|------|-------|----------|
| **编排 Orchestrator** | 概念地图生成器（本对话） | 持有用户意图；开/停闭环；换轨（工程→体验）；向用户播报里程碑；**禁止**两边再向用户要「是否继续」 |
| **验收 Review** | 概念地图验收 `76718d49-…` | 验线上产品；出结构化报告；**直接**交给实现；回归；决定是否满意收工 |
| **实现 Implement** | 概念地图实现 `e89f0c67-…` | 只做报告里的项；改代码→部署；通知验收回归 |

用户只跟编排说话。验收/实现**不得**为「是否开跑 / 方向对不对」再去问用户；有疑义只问编排。

## 站立指令（Standing order）

当前站立指令（由编排更新）：

> **体验优先持续闭环**：审美、交互设计、功能设计。连续跑到验收明确「体验满意、可收工」为止。不是定时任务。工程向 M1–M7 已收工，不再作为本轮目标。

站立指令变更时：编排发一条 priority 消息给两边，并改本段文字。

## 正确数据流（只允许这些边）

```
用户 ──意图──► 编排
编排 ──Kick / Stop / 换轨──► 验收
验收 ──报告──► 实现          （priority，直接交接）
实现 ──已部署──► 验收        （priority，请求回归）
验收 ──里程碑/收工──► 编排   （编排再转述给用户）
实现 ──阻塞/需要决策──► 编排 （不要直接问用户）
```

禁止：

- 验收/实现向用户要「确认开始」
- 编排在闭环进行中重复 Kick「再开始一轮」（除非 Stop 后重开，或换轨）
- 实现自拟需求（无报告不改）
- 三方同时对同一轮发互相矛盾的指令

## 一轮怎么跑

1. **Kick（仅编排）**：站立指令生效后，编排对验收发一次「按站立指令开始」。
2. **验收**：查 https://concept-map-generator.pages.dev/ + 仓库，产出报告（见模板）。
3. **交接**：验收 → 实现（完整报告，priority）。抄送编排一句「已交 N 项」。
4. **实现**：按报告优先级落地 → build → push → Cloudflare 部署。通知验收「commit / 资源 hash」。
5. **回归**：验收逐项 PASS/FAIL；FAIL 写清复现 → 交回实现；全部目标项 PASS 则：
   - 若仍未「体验满意」→ 验收自己开下一张体验清单（**无需编排再 Kick**）
   - 若满意 → 验收通知编排「收工」+ 摘要；编排转告用户；两边暂停。
6. **Stop**：用户说停 / 编排发 Stop → 两边立刻停在安全点（实现可完成当前 commit，不再开新项）。

## 验收报告模板（必填）

```
轨：体验 | 工程
轮次：Ux-N
线上基准：commit / bundle hash
目标：本轮要证明什么（一句话）

阻塞（P0）：
- id | 现象 | 复现 | 期望

重要（P1）：
- id | 现象 | 为何伤体验 | 建议改法

增强（P2，可选）：
- id | 想法

上一轮回归：id → PASS/FAIL + 一句证据
下一动作：交给实现 | 收工 | 等编排决策
```

## 实现回执模板（必填）

```
对应轮次：Ux-N
已做：id 列表
未做：id + 原因
线上：commit / bundle / 时间（Asia/Shanghai）
请验收回归：是
阻塞（若有）：一句话，@编排
```

## 换轨

从「修缺陷」切到「体验」或反过来：

1. 编排更新本文件「站立指令」并 commit。
2. 编排向两边发 **换轨**（priority），写明旧轨结束、新轨目标、是否丢弃旧清单未完成项。
3. 验收开新轨第一轮；实现只消化新轨报告。

## 定时例程

工作日定时例程 **保持暂停**。本 Loop 由站立指令驱动，不靠 cron。
